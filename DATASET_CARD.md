# Dot Reflex Synthetic Trajectories v0 — dataset card

## Summary

A deterministic, fully synthetic dataset for choosing recovery controls from an
agent execution trajectory. It contains no copied private conversations, user
prompts, production logs, or credentials.

## Schema

Every trajectory contains:

- task summary
- execution history
- tool results
- current state
- detected failure signals
- selected control action
- concise rationale
- confidence
- optional recovery instructions
- provenance and split metadata

The public inference contract is in `trajectory.schema.json`. Training records
also contain the gold action, rationale, confidence, recovery instructions, and
provenance metadata; those label fields must never be included at inference.

## Splits

| Split | Target rows | Purpose |
|---|---:|---|
| train | 6,000 | QLoRA supervision |
| validation | 600 | training diagnostics only |
| benchmark | 1,000 | static final evaluation |
| live episodes | 200 | stateful recovery simulation |

The ten actions are balanced within one example when division is not exact.
Benchmark rows use held-out template-family IDs and benchmark-only application
domains. Exact canonical input hashes are required to be disjoint across all
splits. Generator output and overlap checks are saved in
`data/processed/manifest.json`.

Validation data is not called the final held-out benchmark. The benchmark and
live episode receipts remain separate.

## Scenario coverage

- successful progress and verified completion
- repeated tool-call loops and invalid arguments
- edits or completion claims without verification
- compilation, test, and integration failures
- escalating repair attempts and invalid assumptions
- unsafe/destructive operations needing authority
- ambiguous requirements
- model/provider capability failures
- rollback, branching, human escalation, and irrecoverable stop cases

## Files included in this model release

This repository contains the adapter, aggregate evaluation receipts, and this
dataset card. It does not contain row-level training, validation, benchmark, or
episode records. Publishing the model does not imply that a different dataset
already present under the `usedot` account was used for Dot Reflex.

## Source and license

All records are generated by `src/dot_reflex/synthetic.py` under Apache-2.0.
Source inventory: `data/raw/SOURCES.json`. No external dataset rows are mixed in.

## Known limitations

- Controlled templates are less linguistically and operationally diverse than
  independently collected trajectories.
- The generator makes label intent unambiguous more often than real agents do.
- Template-family disjointness does not guarantee semantic independence.
- Live episodes are a simulator, not a production-agent trial.

Consequently, the dataset can test the training pipeline and initial hypothesis,
but cannot by itself substantiate broad production safety claims.

The original generator, processed rows, manifest, and split-overlap receipts are
preserved in the isolated R&D project but are not part of this model-weight
release. Consequently, this Hugging Face repository alone cannot regenerate the
dataset. No private conversations, credentials, user prompts, or production Dot
data were used.
